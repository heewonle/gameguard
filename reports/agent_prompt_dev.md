## v1 → v2: 너무 많이 놓침
- 실제 어뷰저 24명 중 13명을 normal 로 판정. 프롬프트의 "헷갈리는 정상" 목록에 과하게 끌려감
- 설명과 판정이 어긋남: "다계정으로 판단… 따라서 normal"
- ML 확률을 그대로 주었더니 검토 큐 계정의 값이 0.0으로 반올림 → "ML 0.0 이라 정상"이라며 도구 호출 없이 판정
- 고친 것: ML 은 백분위로 전달 / 최소 도구 호출 3회 강제 / 출력 스키마 순서를 summary·evidence → verdict 로 바꿔 설명을 먼저 쓰게 함 / 다계정과 RMT 구분 기준 명시

## v2 → v3: 반대로 다 어뷰징
- 정상 경보 6건을 모두 abuse 로 판정. "ML 점수가 높아 의심" 처럼 **경보 자체를 증거로** 씀
- "골드를 보낸 것" 만으로 RMT 판정, 시세 1.59배 판매를 시세조작으로 판정 (프롬프트는 2배)
- 고친 것: 프롬프트를 **조사 매뉴얼** 형식으로 — 유형별 수치 확인 항목 표, "2개 이상 충족해야 abuse, 1개면 uncertain, 없으면 normal", 경보는 볼 이유이지 증거가 아님을 명시
- 같은 30건으로 다시 맞추면 그 표본에 과적합되므로 **새 개발 표본 B** 로 확인
